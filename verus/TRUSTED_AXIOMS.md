# Trusted axioms

Facts the Verus proofs take without proof. If it is not proven in
Verus, it is here with the reason it is trusted. The trusted base must
stay smaller than the verified base.

CI guards, under `verus/scripts/`: `verify.sh` (every unit, pinned
count, no unproven item outside `axioms_t.rs`, eight Z3 seeds),
`negative_controls.sh` (eighteen twin mutations must fail),
`oracle_sync.sh` (build oracle and moduli against the model),
`seam_guard.sh` (production or `build/` change without a `verus/*.rs`
change fails).

## Model axioms

`verus/axioms_t.rs` holds the tree's four `external_body` proof fns,
the only `external_body` items under `verus/`. The columns
`phi_basis` and `phi_inv_basis` are uninterpreted: the two `phi`
axioms hold of them exactly when they hold of the generated
`TOWER_TO_FLAT_N` and `FLAT_TO_TOWER_N` columns, which
`build/main.rs` checks on every `cargo build`.

## Seams: production code and its Verus twin

A twin transcribes a production function; Verus proves the twin. That
production computes the same thing is trusted: review,
`seam_guard.sh`, and the release-mode differential tests. CI runs
`cargo test --release` on five lanes: aarch64 `pmull`, `pmull-ct`,
fallback, x86, and `x86-ct`. The `-ct` lanes use default features; the
others pass `--all-features`, and `table-math` swaps the conversions,
promotes, `Block8` mul/invert, and the `Block128::mul` dispatch for
lookup tables. Only the `-ct` lanes run the constant-time variants.

## Not modeled

- Constant-time behavior. Timing is not a functional property; Verus
  accepts a variable-time refactor as correct. Separate analysis.
- rustc/LLVM lowering of the intrinsics to instructions. The
  release-mode differential CI on the arm runner is the partial
  mitigation.
- Circuit / arithmetization soundness. Not in this crate.
